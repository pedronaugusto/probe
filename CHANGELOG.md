### Added

- `Schema.Of(Doc)`: a document type's fields as probe indexes them, read at compile time from its `pub const probe = .{ .id = ..., .fields = .{ ... } }`: each field `.text` (with `positions`, `offsets` and `analysis`), `.keyword` or `.numeric` (a `u64`, an `i64` or an aegis scalar of either), any of them `stored`; a declaration that cannot work does not compile, and says why. `Schema.columnValue` gives a numeric value as its column's `u64`, in order. `DocId` (a document's place in its segment, an aegis index), `Id(Doc)` (the program's id for a document, an aegis id of `u64`) and `Limits` (document bytes, term bytes, prefix expansions, query clauses and depth).

- `bitpack`: integers in blocks of 128 packed to the fewest bits that hold the block's largest (`bitsFor`, `pack`, `unpack`, `packedBytes`), in SIMD-BP128's layout of four interleaved lanes, little endian, so every target writes and reads the same bytes; and doc ids as gaps less one (`gaps`, `ungap`), `ungap` refusing gaps that pass the largest doc id with `error.Overflow`.
- `fst`: a minimal finite state transducer from byte strings to `u64`s, built from keys in strictly rising order (`Builder.add`, `error.NotRising` otherwise; `Builder.finish`), each node written once and shared by every key it serves; read with `Fst.parse`, `Fst.get` and `Fst.walk`, which gives the keys with a prefix in order, iteratively, within the caller's key buffer (`error.KeyTooLong` past it). Every node leads only to nodes written before it, so a walk over any bytes ends, and bytes that break a rule are `error.Corrupt`.
- Analysis of a text field (internal; the index reaches it): its words by UAX #29, the segments that hold a letter, a digit or a connector, each indexed as its NFKC_Casefold (xenoglyph); with `.words_and_identifiers`, an identifier also as its parts, cut at what lies between letters and digits and where the case turns (`parseSpan`, `max_record_bytes`, `std.mem.eql`, `HTTPServer`), at consecutive positions from its own, so a phrase of the parts finds it. A term longer than `Limits.term_bytes` is cut on a code point. The stages a field's `Analysis` names are composed at compile time. Depends on xenoglyph.
- A segment's files (internal): each named by its segment in hex and its kind's extension (`.terms`, `.post`, `.pos`, `.len`, `.cols`, `.ids`, `.store`, `.del.<generation>`), and framed by a header (magic, format, kind, segment, little endian) and a CRC-32C footer (warp); a file is read back only once its header says it is the file asked for, in a format this build reads (`VersionTooNew` otherwise), and its checksum matches (`Corrupt` otherwise). Depends on warp.
- A term's postings (internal): its documents and frequencies in blocks of 128, doc gaps and frequencies bit-packed, a short last block as varints, with a skip entry per block holding its last doc, its length and its impacts, the competitive (frequency, length) pairs, or past eight its highest frequency and shortest length. A reader goes forward by `next` and `advance(target)`, passes a block by its skip entry without decoding it, and checks what it reads: doc ids rise inside the segment, each block ends at the doc its entry names, every length stays inside the bytes (`Corrupt` otherwise).
- A term's positions (internal), and their byte offsets when the field keeps them: a chunk per postings block, its tokens in groups of 128 bit-packed (each position's distance from the one before in its document; with offsets each start's distance and each length), a short last group as varints. A reader moves in step with the postings (`enter`, `document`), reads a document's tokens or passes them, a whole group by its bits bytes without unpacking, and checks what it reads (`Corrupt` otherwise).
- A segment's term dictionary (internal): per indexed field an FST from each term to its ordinal, and a table of each ordinal's postings and positions addresses; checked whole when parsed (lengths against the bytes, each FST's key count against its terms), a term's ordinal against its table when looked up (`Corrupt` otherwise).
- A segment built from documents and read back (internal): each document's values, one per field, analyzed into its terms (a keyword's bytes one term), written as the term dictionary, postings, positions, lengths (each document's count of tokens per text field, and their sum) and ids (each document's, an FST from each id to its last document, and each document added after another with its id paired with that one, so every document of an id is found, the last first), each file framed; read back with every address checked against the file it points into and positions present exactly where the schema keeps them.
- Numeric columns (internal): each numeric field's values in blocks of 128 documents, each block with its least and greatest value so a range can pass it whole, its values as their distance from the least packed to 32 bits or fewer, or as they are when the block spans more; read through a cursor that holds a block decoded and checks its values inside its bounds. A segment writes them as its columns file.
- Stored fields (internal): each document's values of the fields the schema stores, in blocks of about 16 KiB compressed with LZ4 (warp), read a document at a time by decompressing its block; the block table is checked whole when read (first documents rising from zero, blocks contiguous, none decoding past the caller's bound), each block's decoded length and every value inside it. A segment writes them as its store file.
- A segment's postings, positions and stored blocks are read from their files positionally (internal), each reader through windows of its own over the file, so a search reads the blocks it walks and no more; the term dictionary, lengths, ids, columns and the store's block table are held in memory, each checked whole by its CRC-32C when read (the store's table by one of its own). A file is opened once its header is checked (`open`), and read whole for its CRC-32C by `verify`; a file cut short under an open reader is `Corrupt`, a read that fails `ReadFailed`, or `Canceled`. Postings carry their skip entries' length and positions their chunk lengths' length, each checked where the entries end.
- An index's writer (internal): the directory's lock (std's advisory lock on its `.lock` file; a second writer is `Locked`, and a dead writer's lock goes with its process), the temporary files a dead writer left removed at open, the newest manifest's segments opened (`SchemaMismatch` for an index written with other fields). Documents are added, deleted (every document of the id added before the delete) and updated, gathered into a segment closed in memory by `refresh` or past `buffer_bytes`. `commit` writes the new segments' files and changed deletion bitmaps, then after a fence the manifest, in one airlock batch at the writer's durability, so a crash leaves the last commit or this one whole; a segment whose every document is deleted leaves the manifest; the manifests past `keep_commits` and every file the kept ones do not name are removed after, what a removal leaves going at the next commit or open.
- An index's manifest (internal): a commit's generation, the fields and term length it was written with, the number the next segment takes, and its live segments with their documents and deletion generations, as JSON (strand) a person can read, one file per commit named by its generation. Read back checked: a format this build reads (`VersionTooNew` otherwise), the schema the index is opened with (`SchemaMismatch` otherwise), the generation its name says, segment numbers rising and below the next, deletions counting at least one document and fewer than their segment's (`Corrupt` otherwise). Depends on strand and airlock.
- `bitmap`: a set of a segment's doc ids, one bit each, as a deletion generation keeps them (`Bitmap` to write, started empty or from the generation before; `View.parse` to read, refusing bytes of another length or with a bit set past the segment's last doc).
